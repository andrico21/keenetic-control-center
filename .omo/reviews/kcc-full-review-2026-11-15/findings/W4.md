# Review: lane W4

I read this as a read-only review of lane W4. I followed the BRIEF and stopped once this report was written.

### W4-01 Explorer and console reads show stored secrets (ns3 blobs) to roles that lack `RevealSecrets`
- severity: high
- kind: security
- rule: project rule (d); overlay keenetic-control-center "(d) Secrets ... never reach ... tool results"
- evidence:
  - `crates/kcc-web/src/authz.rs:257-261`: explorer routes fall to `Read`:
    ```rust
    value if value.starts_with("/ui/advanced") => Permission::RawRci,
    ...
    value if router_section(value) == Some("console") => Permission::RawRci,
    _ => Permission::Read,
    ```
  - `crates/kcc-web/src/page_kit/gate.rs:18-20`: `Risk::Read => vec![Permission::Read]`
  - `catalog/5.1/show.json:7812-…`: `"path": "show running-config"`, `"kind": "Show"`, so its risk is Read.
  - `crates/kcc-web/src/advanced/execute.rs:71-72,97`: `let needed = command_permissions(risk); … Delivery::Read => dispatch.read_root(&built.root()).await`
  - `crates/kcc-web/src/advanced/viewer.rs:94-97,111-118`: only JSON members are masked, by name, and text is passed through as is:
    ```rust
    if !reveal { mask(&mut shown); }
    ...
    pub(crate) fn text(text: &str, locale: Locale) -> Self { let mut viewer = paged(text, locale); ...
    ```
  - `crates/kcc-web/src/page_kit/secret.rs:33-41`: `mask` replaces a member only when its *name* is secret. Secret values inside string content (for example `"    wpa-psk ns3 …"`) are left alone.
  - The same code knows these are secrets. `preview.rs:258-266` (`ns3_redacted`: "every `ns3` payload replaced, whatever the secret registry knows") and `config_page.rs:6-8` (a backup downloads "with its secrets only for `RevealSecrets` … no `ns3` blob").
  - `advanced.rs:78` documents kept responses as "secrets redacted", which is false for text bodies.
  - `cli.rs:206-209` sends Read lines through `client.parse` and renders them the same way.
- impact: The built-in `viewer` role has only `Read`. It can open `/ui/r/home/explorer?path=show running-config` and press Run. It gets the router's full running configuration, including every `password ns3 …`, `wpa-psk ns3 …` and IPsec/PPP secret line. These are the same values the backup download strips for that role. The answer is also kept for download (`keep_response`). In the CLI console, a `RawRci` holder without `RevealSecrets` gets the same through `show running-config`. It also gets the startup config through `more flash:startup-config` (risk Write, so only `RawRci` is needed).
- fix: Run every explorer and console text answer through the same line redaction as `preview::stored`: `kcc_config` `parse` → `redact` → `ns3_redacted`. Alternatively, treat `show running-config`/`more` as needing `RevealSecrets`. Apply it in `Rendered::body`/`Rendered::text` whenever `reveal == false`, and add a test: a viewer runs `show running-config` and receives no `ns3` blob.
- confidence: medium. INFERRED: that a real router's RCI answer to `{"show":{"running-config":{}}}` carries the config lines as strings (the fake router's config holds `wpa-psk ns3`, per `tests/explorer_pages/browse.rs:267`).

### W4-02 Any reader of a router can stop or follow other users' jobs, and job ids are predictable
- severity: medium
- kind: security
- rule: http-services overlay (authorization per resource); BRIEF focus "background jobs (start/poll/stop ownership)"
- evidence:
  - `advanced/jobs.rs:214-219`: there is no owner check.
    ```rust
    jobs.get(job).ok().filter(|record| {
        record.router.as_deref() == Some(router) && record.kind.starts_with(KIND_PREFIX)
    })
    ```
  - `advanced/jobs.rs:187-196`: the cancel handler needs only router scope, plus `RawRci` for `raw` kinds.
  - `system_pages/jobs.rs:244-251`: a diagnostic is stopped after `followed(..)` with no owner check.
  - `job_stream.rs:72-81` and `system_pages/jobs.rs:141-147`: anyone with router scope can follow any job.
  - `kcc-app/src/jobs/job_id.rs:51-68`: `"job-{timestamp:012x}-{:08x}-{entropy}-{sequence:012x}"` uses a per-process constant plus a counter.
- impact: A viewer starts one ping job, which reveals the process prefix. They then try nearby sequence numbers and timestamps against `POST /ui/r/home/system/jobs/{id}/cancel`. That stops an administrator's running diagnostic or explorer job, and they can stream its output. `JobRecord` has no owner field to stop this.
- fix: Store the starting username (or session key) next to the job id: in `keep_output` and in `JobFeeds::follow`. Require it to match in `explorer_job`, `followed`, both `cancel` handlers and both streams, or require an admin permission to act on other users' jobs.
- confidence: high (missing check); medium (enumeration effort).

### W4-03 Router-account protection fails open when kcc's login is empty or the profile lookup fails
- severity: medium
- kind: bug
- rule: RUST_GUIDELINES.md §2 "swallowed errors" (fail-closed); BRIEF anti-pattern "swallowed or downgraded errors"
- evidence:
  - `system_pages/shared.rs:152-157`:
    ```rust
    let fleet = state.fleet()?;
    context::lookup(fleet, user.role(), router).await.ok().flatten().map(|entry| entry.profile.login)
    ```
  - `user_delete.rs:104-106,119`: `let login = profile_login(..).await.unwrap_or_default(); … router_users::plan_delete(ctx, form.name(), &login)?`
  - `user_forms.rs:103-105`: the same pattern feeds `plan_password`.
  - `kcc-domain/src/router_users.rs:182-184`: `if name == profile_login { return Err(DomainError::ProtectedAccount); }`
  - `kcc-app/src/registry.rs:59-60`: `/// Primary management login; may be empty for a token profile.`
- impact: For a token-auth router, `login == ""`. For any router, a registry read error makes it `""` too. Either way the "account kcc signs in with" guard never matches. A `ManageUsers` holder can then delete, or set a new password on, the router account kcc uses. kcc loses access after the bracket. A fail-safe timer may roll back only if the session dies before the disarm (INFERRED).
- fix: Make `profile_login` return `Result<String, _>`. Refuse the change (fail closed) when the lookup fails or the login is empty. For token profiles, record and compare the token's account.
- confidence: medium (INFERRED: which account a token profile signs in as).

### W4-04 About 50 `pub(crate)` async handlers in scope lack cancel-safety annotations, including write paths
- severity: medium
- kind: guideline, KNOWN-BACKLOG
- rule: RUST_GUIDELINES.md §5 "Annotate every async fn with cancel safety" (1188)
- evidence:
  - Write paths without a comment: `advanced/rci.rs:127` (`send`), `system_pages/component_commit.rs:50` (`commit`: `workflow().begin` and then a job start), `user_forms.rs:66,137`, `user_delete.rs:89`, `storage_actions.rs:85,117,190`, `keendns_access.rs:54,113`, `keendns_forms.rs:179,215`, `schedule_forms.rs:87`, `schedule_actions.rs:141`, `component_queue.rs:46,70`, `diagnostics.rs:117`, `dns_vpn/dns_pages.rs:136,175`, `vpn_import.rs:76`, `vpn_pages.rs` `submit`, and `vpn_actions.rs` `switch`/`service`/`delete`.
  - Reads without a comment include `advanced/jobs.rs:179` and `job_stream.rs:63`.
  - Siblings are annotated (`cli.rs:148`, `execute.rs:40`), so the omission is inconsistent.
- impact: `docs/BACKLOG.md:77` says "Ten non-public production async fns" lack the comment. This scope alone has about 50, several of which run management brackets. A future `select!`/timeout wrapper would get no warning.

- confidence: high

### W4-05 Existence guards swallow read errors (one path lets "Add account" overwrite an existing account)
- severity: low
- kind: anti-pattern
- rule: BRIEF "swallowed or downgraded errors"
- evidence:
  - `user_forms.rs:201-206`: `accounts(domain, None).await.ok()?…find(..)`, used at `:98` as the name-taken guard (`Ok(_) if find(&domain, &name).await.is_some()`).

### W4-07 Global caps evict other sessions' downloads and running jobs' answers
- severity: low
- kind: bug
- rule: none
- evidence:

### W4-09 Raw-form secrets are held in plain `String`s with derived `Debug`
- severity: low
- kind: guideline
- rule: project rule (d) "Secrets live in `secrecy`/`zeroize` types … never … `Debug` output"
- evidence:
  - `rci_check.rs:24-34`: `#[derive(Debug, Default, Deserialize)] pub(crate) struct RciForm { … body: String, …}`
  - `cli.rs:50-54`: `#[derive(Debug, Default, Deserialize)] pub(crate) struct CliForm { line: String, …}`, where the line can be `user x password plain …`.
  - `request.rs:161-162`: explorer secrets are copied as `Value::String(text.to_owned())`, and the `pairs` `Vec` is dropped without zeroizing.
  - `vpn_import.rs:258-261`: `let bytes = field.bytes().await…; SecretString::from(text.to_owned())` leaves the private key in the un-zeroized `Bytes`.
- impact: Any future `tracing::debug!(?form)` prints router passwords. Plaintext copies stay in freed memory.
- fix: Implement a manual `Debug` that omits `body`/`line`. Zeroize the `pairs`/`Bytes` copies, or move the text straight into `SecretString`/`SecretValue`, as `secret_pages::dialog::take` does.
- confidence: high (no current Debug print found)

## Clean
- Every raw request is validated before sending. The explorer validates by path and then as the root object (`request.rs:60-75`). The console validates by path, or each root item up to `MAX_BATCH`=50 with body and path caps (`rci_check.rs:68-153`). CLI lines go through `validate_cli`, which rejects quotes and the characters `; | & $ < >`. Validation runs again on send.
- Raw DELETE is classified Destructive, and management comes from the validated request (`rci_check.rs:193-228`). Console sends require `RawRci` plus the risk's permissions. Unvalidated CLI lines additionally require `ManageRouters`.
- Confirmations: destructive actions (storage, component commit, raw destructive) need the typed router name, and management changes use the bracket dialogs.
- Templates use askama escaping for router text, status messages and problems. `|safe` is used only to embed nested askama templates.
- The viewer is capped at 256 KiB and paged, and a larger answer is offered as a download.
- Router-user passwords and WireGuard PSKs are taken out of the form into `SecretString` before `Params`/audit, and are zeroized on mismatch.
- `.conf` import errors name a line and field, never a value, and the upload has its own 64 KiB limit and 413 dialog.
- Audit records carry field names only (`field_names`, redacted batch items), never values.
