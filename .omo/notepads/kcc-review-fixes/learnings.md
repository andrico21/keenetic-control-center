## [2026-11-16] Todo 5 progress (H7: F-01, SEC1-05, W1-01; worktree wt/r5)
- `crates/kcc/src/state_watch.rs`: `StateWatch` polls `api_keys.json`/`users.json` every 2 s (stat by inode+mtime ns+size in `spawn_blocking`, then content). Keys: set of (name, hash, role); a change calls `TransportReload::reload_keys` (the Web keys page path, now serialized by a `Mutex` so an earlier read cannot install over a later one). Users: `WebState::end_stale_sessions()` re-reads `AccountStore::standings()` and ends sessions whose account is gone/disabled/other role/other password fingerprint.
- One task owns the watcher: `select!` over the 2 s `Interval` and the SIGHUP `Signal`; SIGHUP runs the same pass (forced), then the existing `kcc.toml`/roles reload, whose "configuration reloaded from SIGHUP" line stays last (serve_refresh waits on it). The watcher starts in the kit's reload callback (keys need the reload handle).
- Fingerprint = SHA-256 of the opened PHC string (`kcc_app::accounts::standing::PasswordFingerprint`, Debug redacted), kept only in `Session`. Login reads it BEFORE `authenticate` (a reset in between makes the old password fail, or the session mismatches and ends). Own password change uses `AccountStore::change_password_for_session` (returns the new fingerprint) and `SessionStore::set_fingerprint`.
- Race design: `SessionStore` has an `account_reads: RwLock<()>`; sign-in and own password change hold a read guard from the account read until the session records it; `end_stale` holds the write guard across its read and the session sweep. Without it a pass could judge a session against an older read and log the user out of their own new session (or miss a reset).
- Logs: `kcc::state_reload` debug per real reload (`file` field); `kcc::state_watch` debug "rewritten without a change" and a start event with `interval_ms`, warn (once per file version) when a file cannot be read/parsed. ## [2026-11-16] Todo 8 part B-08 (wt/r8b): CliCommand binds its line to its request
- `CliCommand::new`/`secret` are fallible (`SecretCommandError::Line`) and call `ValidatedRequest::renders_cli(words)`: the words (config_text parse: quotes unquoted, `ns3` decoded, exactly one line) must match a catalog form of the request's own path, and every argument of the command must be in both the line and the body or in neither, with the same text. Context words (interface name, ACL name, peer key) are checked by type only: a leaf body does not carry them. Keyword alternatives that are not arguments (tcp/udp, `disable`/`schedule` after `no rule N`) are free. A raw (unvalidated) request takes only its own words. `from_template` keeps its own `validate_grammar`.
- The request keeps its catalog view (`Origin(Catalog)`, compared by version+model) so the check runs in the view that validated it.
- Shared grammar fixes (kcc-catalog `cli_grammar.rs`/`cli.rs`, used by validate_cli too): a leading `(group)` naming the command's first word is that word (`(vpn-server)`, `(ndns)`, `(show)`...); the parent path is found by the form's keywords as an ordered subsequence (`mws member <member> reboot`); synopses with 2n lines whose halves repeat (positive lines, then the same lines for `no`) are split by polarity; `<a> [: <b>]` reads `a:b` or `a b` (the remaining word count decides); a `no` line may be `no` + a full positive form (binding only).
- Generator (`xtask/src/catalog_build/corrections.rs`): a bare optional word naming a typed (non-Keyword, non-Boolean) Arguments row becomes that argument (`[ mac ]` -> `[‹mac›]`); `catalog/synopsis-errata.json` replaces a synopsis (`nextdns assign`, `oc-server pool-range`) or adds an omitted command with typed arguments (`interface vlan-id`). `new-index` maps to Integer in `inferred_value_type` and left `untyped-arguments.json`. The three versions regenerate deterministically from the cached extraction.
- The fake router log keeps only the last line of a batch; a segment trunk step's batch ends with its port cleanup (`no interface Gi0/N`), so binding tests use segments without switch ports.
- RED for an API change: run the new tests in a `git archive HEAD` scratch copy carrying only the catalog side; for kcc-app a two-line trait reads master's infallible constructor as "not refused".
