## [2026-11-16] Todo 5 progress (H7: F-01, SEC1-05, W1-01; worktree wt/r5)
- `crates/kcc/src/state_watch.rs`: `StateWatch` polls `api_keys.json`/`users.json` every 2 s (stat by inode+mtime ns+size in `spawn_blocking`, then content). Keys: set of (name, hash, role); a change calls `TransportReload::reload_keys` (the Web keys page path, now serialized by a `Mutex` so an earlier read cannot install over a later one). Users: `WebState::end_stale_sessions()` re-reads `AccountStore::standings()` and ends sessions whose account is gone/disabled/other role/other password fingerprint.

- Fingerprint = SHA-256 of the opened PHC string (`kcc_app::accounts::standing::PasswordFingerprint`, Debug redacted), kept only in `Session`. Login reads it BEFORE `authenticate` (a reset in between makes the old password fail, or the session mismatches and ends). - Race design: `SessionStore` has an `account_reads: RwLock<()>`; sign-in and own password change hold a read guard from the account read until the session records it; `end_stale` holds the write guard across its read and the session sweep. ## [2026-11-16] Todo 8 part B-08 (wt/r8b): CliCommand binds its line to its request
- `CliCommand::new`/`secret` are fallible (`SecretCommandError::Line`) and call `ValidatedRequest::renders_cli(words)`: the words (config_text parse: quotes unquoted, `ns3` decoded, exactly one line) must match a catalog form of the request's own path, and every argument of the command must be in both the line and the body or in neither, with the same text. Context words (interface name, ACL name, peer key) are checked by type only: a leaf body does not carry them. Keyword alternatives that are not arguments (tcp/udp, `disable`/`schedule` after `no rule N`) are free. A raw (unvalidated) request takes only its own words. `from_template` keeps its own `validate_grammar`.
- The request keeps its catalog view (`Origin(Catalog)`, compared by version+model) so the check runs in the view that validated it.
- Shared grammar fixes (kcc-catalog `cli_grammar.rs`/`cli.rs`, used by validate_cli too): a leading `(group)` naming the command's first word is that word (`(vpn-server)`, `(ndns)`, `(show)`...); the parent path is found by the form's keywords as an ordered subsequence (`mws member <member> reboot`); synopses with 2n lines whose halves repeat (positive lines, then the same lines for `no`) are split by polarity; `<a> [: <b>]` reads `a:b` or `a b` (the remaining word count decides); a `no` line may be `no` + a full positive form (binding only).
- Generator (`xtask/src/catalog_build/corrections.rs`): a bare optional word naming a typed (non-Keyword, non-Boolean) Arguments row becomes that argument (`[ mac ]` -> `[‹mac›]`); `catalog/synopsis-errata.json` replaces a synopsis (`nextdns assign`, `oc-server pool-range`) or adds an omitted command with typed arguments (`interface vlan-id`). `new-index` maps to Integer in `inferred_value_type` and left `untyped-arguments.json`. The three versions regenerate deterministically from the cached extraction.
- The fake router log keeps only the last line of a batch; a segment trunk step's batch ends with its port cleanup (`no interface Gi0/N`), so binding tests use segments without switch ports.
- RED for an API change: run the new tests in a `git archive HEAD` scratch copy carrying only the catalog side; for kcc-app a two-line trait reads master's infallible constructor as "not refused".

## [2026-11-16] Todo 27 design (wt/r27; B-01, SEC2-05, B-03, SEC2-04, B-14)
- Lock order: the writer takes the cross-process append lock (`StateStore` lock `audit.jsonl`), then, inside it: open the active file by path (read+append) -> repair a torn tail -> read the chain head from the tail -> hash -> rotate/prune if needed -> write+fsync. No other lock is taken while it is held. At spawn: `try_lock` once (non-blocking); held -> full `verify_chain`, then the same repair; busy -> full `verify_chain` only (the writer repairs before its first append under the lock).
- Tail read: the active file is opened by path under the lock every append, so a rotation by another process (rename + new file) is always seen: identity is whatever sits at the path while the lock is held, and the size is taken from that same handle (`metadata().len()`); no handle or seq/hash is cached across lock releases (the dead WriterState fields are gone). The last complete line is read by seeking back from the end in 4 KiB blocks; when the active file is empty, the newest non-empty archive is read the same way; none -> genesis.
- What the tail read trusts / does NOT prove: it parses the last complete line and recomputes that entry's own hash (a forged last line is refused). It does NOT prove that the entry links to its predecessor, that earlier entries or older archives are intact, or that no archive was removed. Those are proven only by full verification (`verify_chain`: `kcc audit verify`, the Web audit page, writer spawn at startup and every CLI run).
- A complete last line that does not parse or whose own hash is wrong is refused (writer stops, file untouched); it is never truncated.
- Torn tail = the active file does not end in `\n`. The bytes after the last `\n` are copied to a new owner-only `audit.jsonl.torn-<unix-ts>` (create_new; `-2`, `-3`... on a name clash), fsynced with the directory, then the active file is truncated to the last `\n` and fsynced, then an `audit.repair` entry (actor system/system, params `{file, bytes}`, outcome `success`) is appended through the normal path. Crash after the copy and before the truncate -> the next start copies the fragment again (a duplicate quarantine file, never a loss); crash after the truncate and before the repair entry -> a valid chain, nothing left to repair.
- Full verification skips an unterminated last line of the ACTIVE file only (crash debris or another process's in-flight append, not an entry); an unterminated archive tail is still parsed strictly.
- Module split: `audit/chain.rs` (file listing, the one line reader `for_each_line`, `entries(dir, Check::{Chain,Parse})`, hash rule moved verbatim), `audit/tail.rs` (backward block scan, `chain_head`, `last_entry`, `torn_start`), `audit/repair.rs` (quarantine + `audit.repair` event), `audit/state.rs` (WriterState: no cached chain fields, opens the active file by path per append). `verify_chain`/`read_entries` stay thin `pub fn`s in audit.rs (no `pub use`). ## [2026-11-17] Todo 36 design note (jobs/backups bookkeeping)
- Lock files today: `job-<id>.lock` (per-record, taken by `JobRunner::persist` around each record write) and `job-owner-<id>.lock` (held by `JobOwnership` for the lifetime of the running job; `is_held` probes it with try_lock during recovery). ## [2026-11-17] Todo 39 design note (wt/r39; A-02, N5, A-09, A-14, A-15)
- Cookie refresh rule: `Manager::refresh_session(response, sent)` is the only writer of a sliding refresh. It does nothing for a 401. Otherwise, under the one `session` std mutex, it compares the current cookie with the snapshot the request was SENT with (`same_cookie`: name + value); only on a match does it parse the matching `Set-Cookie` and replace value + expiry. Compare and write happen in one lock section, so a late response to a request sent with old cookie A can never overwrite a newer B. Two responses to the same cookie both refresh the same issued cookie (last writer wins, same value). A malformed matching cookie (e.g. `name=; Max-Age=0`) is ignored: the current cookie stays, the response that was already applied is returned as is; the next 401 re-authenticates. Retry responses refresh against the retry snapshot. The GET /auth 200 path refreshes against the session held at that moment.
- `parse_set_cookie`: reads the name from the raw bytes before `=` first; a header with another name is skipped without `to_str`, so an unrelated non-ASCII cookie is absent, not an error. Without an expected name (ndw4 pending cookie) an unparsable header is skipped. A matching malformed cookie is still an error for the auth handshake callers.
- Digest state machine (under the tokio mutex): first send signs with the stored challenge (count+1) if any. On 401: parse the new challenge outside the lock, then under the lock: stored nonce == new nonce -> keep the stored challenge (count continues), else replace; sign (count+1) with the stored one in the same lock section. No count is ever reset for an identical nonce; only one challenge is stored.
- Argon2 cap flow: `[outbound] argon2_max_iterations` (default 16 via manual `Default for OutboundConfig`, range 1..=64 checked in `Config::from_toml_str`) -> `RouterRegistry::new` keeps it -> every `RciClientOptions.auth` the registry builds gets `max_argon2_iterations` -> `Manager::with_auth` refuses outside 1..=64 (Validation) -> `Exchange` carries the cap -> `Reply::challenge` refuses `iter > cap` with `CostTooHigh` before the key cache and before `Keys::derive` (a refused cost never reaches Argon2). `Options::default()` is 16 too (library default = config default).
- Timeouts: `session::map_reqwest_error` is pub(crate) and used by every send in auth_token, auth_digest and auth_ndw4.

## Cargo cache hygiene (orchestrator, todo 52 review)
