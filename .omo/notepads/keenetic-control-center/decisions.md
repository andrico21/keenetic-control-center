## 2026-11-06: kcc-app write/MCP surface amendment
- `ChangeRequest::new(catalog_path, rci_path, body, verify, permission, audit_params)` stores `permission: Permission`; `ChangeSet::apply` authorizes that exact value. `ChangeWorkflow::begin` now requires `Permission::Read` only, because beginning acquires the lease and reads baseline/catalog state but performs no mutation; every mutating method retains its real operation-specific authorization (`apply`, `apply_cli`, `save`, `commit`).
- CLI writes use `CliCommand::new(line, validated: kcc_catalog::ValidatedRequest)` inside `CliChangeRequest::new(commands, verify, permission, audit_params)`, executed by `ChangeSet::apply_cli(&mut self, request) -> Result<CliChangeResult, WorkflowError>`. The method performs operation authorization, conflict check, automatic backup, `RciClient::parse` for one command or `parse_batch` for many, read-back verification, expected-last-change refresh, and audit append. `save()` and `commit()` remain specialized because they require no automatic backup/read-back spec and finish through `wait_saved`, which owns persistence polling and its distinct audit result.
- Structured job progress is `JobProgress::{OutputLine(String), Structured(serde_json::Value)}` carried as `JobEvent.detail: Option<JobProgress>`. `JobContext::progress(u8)` remains source-compatible; `JobContext::structured_progress(JobProgress)` emits the latest percentage plus the typed payload.
- Registry policy APIs are `pub fn authorize(&Role, Permission, &str) -> Result<(), RegistryError>` and `pub fn scope_matches(&[String], &str) -> bool`; `glob_matches` is `pub(crate)` so all external callers share authorization/scope semantics without exposing the lower-level matcher.

## 2026-11-06: Todo 45 prerequisite - genuine CLI catalog validation
- Public API: `Catalog::validate_cli(&self, line: &str, authorization: RawAuthorization) -> Result<ValidatedRequest, Vec<ValidationIssue>>`. MCP can pass its existing raw authorization flags; known supported lines return POST requests with catalog path, named JSON arguments, existing catalog risk, and `unvalidated: false` through `Catalog::validate`. No caller-side path or JSON reconstruction is required.
- Ordering exists upstream: `xtask/src/catalog_build.rs` serializes ordered `Grammar::Sequence` nodes into each command's `synopsis`; runtime `RawCommand` previously discarded this field. Runtime now preserves these facts in a private synopsis map. `Command.arguments` remains unchanged. `ip host <domain> <address>` is tested specifically because synopsis order differs from BTreeMap order. No codegen or dependency change was needed.
- Conservative support: fixed positive forms with zero, one, or multiple declared arguments; each argument consumes exactly one whitespace token, including String. Integer tokens become JSON integers and all scalar format/range checking delegates to the existing validator. Fixed negative forms with no arguments require `prefix_no` and a separate matching synopsis form. The generator strips `no` and concatenates synopsis lines; the parser recognizes the repeated identical context-group boundary observed in the source manuals, and rejects negative forms with argument tails rather than guessing their meaning.
- `UnsupportedCliSyntax { path }` rejects missing/warning-bearing synopses, optional or alternative nodes in the selected form, mismatched command contexts, duplicate/missing argument metadata, and other grammar the fixed-form parser cannot establish confidently. For example, `system reboot 60` is intentionally unsupported because its synopsis has optional alternatives. This is an honest limitation even when administrator raw permissions are present; known command failures never silently downgrade to raw.
- `InvalidCliSyntax` rejects empty lines, unsupported quoting/escaping, control characters other than tabs, semicolons/pipes, and wrong arity. The parser chooses the longest literal token prefix found through `Catalog::lookup`; it does not invent context interpolation for forms such as `interface Bridge0 ...`.
- Unknown commands with no catalog prefix delegate to `validate_with_options` with `unvalidated: true`. Both `raw_rci` and `admin_manage_routers` are required by the existing gate. Successful raw metadata retains the original line in `path` and `{ "command": line }` in `value`, with management risk and `unvalidated: true`. These fields describe a CLI escape, not an RCI endpoint; pass the original line to `CliCommand::new` and preserve the unvalidated audit marker.

## 2026-11-06: Todo 34 Web authentication boundary
- Sessions are process-local `tokio::sync::RwLock<HashMap<SessionId, Session>>` entries. Session ids and CSRF tokens are independent 32-byte `SysRng` values encoded as unpadded base64url; `Debug` redacts both. `SessionStore` checks idle and absolute Unix-clock deadlines on access and runs a skipped-tick periodic sweep. Login removes the anonymous id before inserting the authenticated replacement; privilege rotation uses the same replacement path and invalidates the user's other sessions. Password change preserves the requesting session and invalidates every other session for that username.
- Cookie transport is an explicit startup fact in `WebStateConfig`, not inferred from request headers: TLS uses `__Host-kcc_session` with `Secure; HttpOnly; SameSite=Strict; Path=/`; loopback plain HTTP uses `kcc_session` with the same flags except `Secure`. The already-committed `Config::web_allowed_origins` remains the startup authority for refusing unsafe non-loopback HTTP and deriving browser origins.
- CSRF middleware protects every non-safe method, including login: it requires the session-bound `X-CSRF-Token` in constant time, exactly one allowed `Origin`, and absent or `same-origin` `Sec-Fetch-Site`. `app.js` supplies the header in `htmx:configRequest`; no token or session id enters a URL or log. Static assets remain public; login GET creates an anonymous session; protected pages run CSRF, authentication, then route-table authorization. Unauthenticated protected requests redirect to `/ui/login`; authenticated permission failures render the existing localized 403 page.
- Route authorization maps current and planned route families to `Permission` (`admin`/ManageUsers, `audit`/ViewAudit, `migration`/Migrate, `configuration`/Write, `advanced`/RawRci, `routers`/ManageRouters, default/Read). `/ui/router/:router/...` additionally delegates scope matching to `kcc_app::registry::authorize`, preserving the kit-compatible role scope contract.
- Login and password verification run through `spawn_blocking` around `AccountStore`; all non-success authentication variants render the same credential error. Login success/failure/lockout, logout and password change append `ActorKind::Web` audit events with stable action/outcome ids and no credential parameters. The no-admin state is closed and shows only the `kcc admin init` instruction.
- Verification: focused auth suite 7/7 with evidence at `.omo/evidence/task-34-keenetic-control-center.log`; full G0 and `cargo xtask assets-check` pass. LSP diagnostics timed out three times; compiler and strict workspace Clippy diagnostics are clean.
