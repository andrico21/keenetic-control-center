## Todo 18 (kcc-app config + state store)

- KCC_* env vars (list = `settings::KCC_ENV_VARS`, test-pinned to what is read): KCC_WEB_ENABLED, KCC_WEB_SESSION_IDLE, KCC_WEB_SESSION_ABSOLUTE, KCC_WEB_LOGIN_MAX_FAILURES, KCC_WEB_LOCKOUT, KCC_WEB_DEFAULT_LOCALE, KCC_WEB_PUBLIC_URL, KCC_MCP_HTTP_ENABLED, KCC_MCP_STDIO_ENABLED, KCC_MCP_READ_ONLY, KCC_MCP_ALLOW_DESTRUCTIVE, KCC_MCP_MAX_RESULT_BYTES, KCC_OUTBOUND_ALLOWED_NETWORKS, KCC_OUTBOUND_ALLOWED_SUFFIXES, KCC_OUTBOUND_ALLOW_LOOPBACK, KCC_STATE_DIR, KCC_BACKUPS_KEEP_LAST, KCC_BACKUPS_MAX_AGE, KCC_AUDIT_RETENTION, KCC_CLI_ROLE, KCC_CLI_ROUTER_SCOPE, KCC_PRIVACY_REDACT_CLIENTS_IN_MCP. Bools: true/false/1/0; durations: humantime; lists comma-separated. `[[routers]]` has no env overrides. Plus `KCC_MASTER_KEY_FILE` (secrets). Tests inject the env through `Config::apply_kcc_env_overrides_with(lookup)` (no `set_var`: unsafe is forbidden).
- Encryption: XChaCha20-Poly1305 (`chacha20poly1305` 0.11.0, features alloc+getrandom+zeroize, RustCrypto 0.11 generation = kit's), 32-byte raw master key file, random 24-byte nonce per seal (`XNonce::try_generate`, OS RNG), AAD = router id, stored as `SealedSecret {alg:"xchacha20poly1305", nonce, ciphertext}` (base64 0.23 STANDARD, same as kit). Key path: `KCC_MASTER_KEY_FILE`, else `<config dir>/kcc/master.key`; created 0600 in a 0700 dir and published with `hard_link` so concurrent first runs never overwrite each other's key; unix load refuses mode & 0o077.
- Platform dirs are hand-rolled (XDG_STATE_HOME/XDG_CONFIG_HOME or ~/.local/state, ~/.config; Windows LOCALAPPDATA/APPDATA; macOS ~/Library/Application Support) because `dirs` 6 pulls `option-ext` (MPL-2.0, rejected by deny.toml). Windows/macOS branches are compile-unverified on this host (windows-gnu clippy needs a mingw C compiler for ring).
- Locking: std `File::lock`/`try_lock` on `<file>.lock` and `leases/<router>.lock`; `update`/`write` block, `try_lock`/`try_lease` fail with `StateError::StateLocked`.

## Todo 19 (permissions, accounts, API keys, audit)
- rmcp-server-kit 3.21.1 API confirmed from its checked-out source/docs: `auth::generate_api_key() -> Result<(String, String), RmcpServerKitError>` returns one-shot plaintext plus an Argon2id PHC hash; `auth::ApiKeyEntry::new(name, hash, role)` is the supported conversion; `rbac::RbacConfig::with_roles(Vec<RoleConfig>)` and `RoleConfig::new(name, allow, hosts)` accept exact tool names and the kit's `*`-only, case-sensitive host glob semantics.
- KCC roles map each `Permission` to exact registered tool names; router scopes pass unchanged to `RoleConfig::hosts`. Built-ins cannot be overridden by `roles.json`.
- `users.json` stores the Argon2id PHC string encrypted with todo 18's `MasterKey`/`SealedSecret`, username-bound as AAD. Account hashing is fixed to Argon2id v19 m=19456 KiB, t=2, p=1. Lockout state updates through `StateStore::update` and an injected Unix clock, with no sleeps in tests.
- `api_keys.json` stores only kit-generated hashes and metadata; plaintext is returned once inside `SecretString`. `audit.jsonl` remains append-only plaintext metadata but rejects secret-shaped parameter keys, uses one mpsc writer task, hashes canonical fixed-order JSON, and carries sequence/hash continuity across 50 MiB rotations.
- Direct dependencies `argon2 0.6`, `sha2 0.11`, and `tokio` reuse versions already present through rmcp-server-kit; no second RustCrypto generation was introduced. Full G0 and deny/audit/vet/machete/tree gates passed.

## Todo 56: platform privilege APIs
- Linux/Unix use direct `rustix` 1.1.6 (`process`, `thread`) plus `caps` 0.5.6; no `nix`. Windows uses target-gated `check_elevation` 0.3.0, the maintained successor to `is_elevated`; it is BSD-3-Clause, depends only on `windows-sys` 0.52.0, and returns a Windows error so startup fails closed when token elevation cannot be queried. The Windows branch is compile-unverified on this Linux host.
