## Todo 15: config text and NS3
- NS3 encode selects a total block length of 18, 36, or 72 bytes from `plaintext_len + 3`; appends NUL and deterministic MD5-derived filler; applies the Fibonacci-stream XOR then payload-wide XOR mask; inserts MD5 bytes 0 and 1 at `x2 % (length - 1)` and `length / 7`; Base64 encodes. Decode removes markers in reverse order, applies the same two involutions, and truncates at NUL. The PowerShell Gallery script says `length / 8`, but the public Python reference, the verified todo-53 shell port, and all three KATs require `length / 7`.
- Config parsing ignores non-header `!` lines, detects the smallest positive indentation as one level (covering 1- and 4-space exports), rejects non-multiples and skipped levels, and treats line numbers as source metadata rather than AST identity so canonical print/parse equality is structural.
- Tokenization unescapes only `\\"` and `\\\\` inside quoted arguments and folds `ns3 <blob>` into `Token::Ns3`; canonical printing re-quotes empty/whitespace/quote/backslash-containing words, always uses one-space levels, and writes `!` after every top-level block.
- Full workspace fmt can be transiently blocked by concurrent agents' unformatted `kcc-app`/`kcc-testkit` edits; crate-scoped fmt plus strict clippy/tests/rustdoc verifies todo 15 without touching those owned paths.

## Todo 13: catalog parser and committed data
