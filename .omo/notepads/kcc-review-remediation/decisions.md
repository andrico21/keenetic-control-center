## [2026-11-13] Todo 2 decisions (worker r2)
- No existing test expectation changed. `component_install_requires_a_fresh_plan` only gained assertions (no timer armed, no arm/reboot line after `components commit`).
- A failed `components commit` call (terminal CLI Err) is treated as "not yet rebooted": kcc sends the disarm (Ok -> original Workflow, Err -> FinishFailed). The plan's "no disarm after commit was sent" applies only once the commit call returned Ok; an Err may mean the commit was refused before sending, and in scheduled-reboot mode `show last-change` would not reveal the still-armed reboot timer, so a last-change read alone could leave it unreported.
- Post-arm outcome lives in a new `crates/kcc-migrate/src/apply/settle.rs` (`Stop::{Armed,Rebooted}`, `Stop::settle`, `Stop::unconfirmed_arm`) so `preflight::prepare` stays under the 100-line clippy limit; `components::install` now returns `Result<(), Stop>`.
- `ArmUnconfirmed` is NOT in the Web `BEFORE_CHANGES` retry lists: offering a retry while a timer may be armed contradicts its message.
- `FinishFailed` is newly reachable from a run's preflight, so it is also mapped in the name-based Web run texts (`migrate_wizard/run.rs`, `presets_page/events.rs` -> `management-outcome-unknown-armed`) and in MCP `map_apply` (-> `management_outcome_unknown_fail_safe_armed`; it previously fell into the `_ => validation_failed` arm).
- Testkit: `FaultInjection::fail_parse_matching` now applies before the migration intercept (agreement `dpn/eula accept`, ns3 lines), matching BEHAVIOUR.md ("rejects the next matching parser lines"); needed to inject an agreement-accept failure after the arm.
- Scenario (3) (refused disarm) uses an invalid component name as the post-arm failure, because one `fail_parse_matching` slot cannot both refuse `dpn accept` and `no system ...` without also refusing the arm line.

## [2026-11-13] Todo 3 decisions (worker r3)
- Path: `kcc_domain::configuration::close::{Close, Closed, close}` (new file `configuration/close.rs`, no `pub use`); `configuration.rs` is already over the LOC ceiling.

- Engine `commit` now detects the router (for the RouterCtx) before the commit/save in both modes; a detect failure there is `FinishFailed` (armed, nothing sent). Before: router mode never detected; scheduled mode detected after save, so a detect failure was `SavedDisarmFailed`.

The `cli-saved` note is now printed whenever the step saved, i.e. also after a successful router-mode commit+save (before: scheduled mode only).
- Behavior change (GAP-4 fix): `kcc config failsafe commit` in router mode now sends `system configuration save` after the commit; `kcc config failsafe rollback` and `kcc preset finish rollback` in scheduled-reboot mode send `system reboot` (body `{}`) instead of the native rollback. Standalone config rollback in that mode emits new key `failsafe-rollback-rebooting`.

- docs/MIGRATION.md finish paragraph updated (router-mode commit then save; scheduled rollback reboots).

## [2026-11-13] Todo 9 decisions (shared safety bracket)
- `recovery::Failure` stores `fate: Option<ArmedFate>` + `sent` + `applied` instead of four bools (`armed`, `sent`, `applied`, `saved`): four bools trip `clippy::struct_excessive_bools`, and storing the fate makes "armed" and "which armed message" one fact. `is_armed()` = `fate.is_some()`; public API unchanged (`armed`, `is_armed`, `applied`, `into_source`, `finish`, `finish_applied`).
- `Saved` is marked by the new `pub(crate) Failure::saved(source)`, used only by `close` (Save in scheduled-reboot mode, save ok + disarm refused). The migration engine (`kcc-migrate/src/apply/finish.rs`) now maps `fate() == Some(Saved)` -> `SavedDisarmFailed`, `(None, applied)` -> `CommittedSaveFailed`, else `FinishFailed` (same outcomes as the old `(applied, armed)` match).
- `Failure::message_key() -> Option<MessageKey>`: armed fate key; `management-not-applied` only when nothing was sent after/at the arm and the timer is off (arm refused + disarm ok, or refused before the arm); `None` when the work was sent and the disarm accepted (callers show the original error). Never an armed key for an unarmed failure.
- `guarded` refuses an unheld request with `WorkflowError::Audit(AuditError::WriterUnavailable)`, the error the Web page kit already uses for `brackets::hold() == false`.
- Counter ownership: `kcc_app::brackets::Brackets` lives in `ChangeWorkflow` (created in `ChangeWorkflow::new`, so one per process; `ChangeWorkflow::new` signature unchanged). kcc-web's `Claim` no longer counts; the Web's open-coded bracket (`page_kit/change.rs`) calls `changes.enter_bracket()` right after `brackets::hold()`, so `kcc serve` still waits for Web brackets (serve_bracket green). `wait_for_brackets` now drains `services.workflow.brackets()` always (count 0 when the Web is off, as before). Log text and docs/MONITORING.md wording left as is (todo 12 owns the shutdown wiring).
- Changed test fixtures (no assertion changed): `kcc-web/src/brackets/tests.rs` handler enters the shared `kcc_app::brackets::Brackets` after `hold()` (the claim no longer counts) and `own` takes no state; `kcc-domain/tests/close.rs` and `tests/verification_coverage/tests/execution.rs` pass `SafetyNet::CONTROL_PERMISSION` to `arm`/`keep_alive`.
- Every pre-existing `SafetyNet::{arm,disarm,keep_alive}` caller passes `SafetyNet::CONTROL_PERMISSION` explicitly (CLI change/persist/dom_jobs, MCP raw_change, Web page_kit, migrate preflight/settle/execute, interfaces guard, close). Migration preflight's arm moved into `Stop::arm` (settle.rs) only because the extra argument pushed `prepare` over 100 lines.
