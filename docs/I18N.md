# Internationalization

Every user-visible string lives in `crates/kcc-i18n/locales/<lang>/*.ftl`, written in
[Project Fluent](https://projectfluent.org/fluent/guide/) syntax. English (`en`) is the
source of truth. Code refers to messages only through the generated constants in
`crates/kcc-i18n/src/keys.rs`, so naming a message that does not exist is a compile error.

## Locales and review status

| Locale | Language   | Status                                       |
|--------|------------|----------------------------------------------|
| `en`   | English    | Source of truth                              |
| `ru`   | Russian    | Machine-assisted translation, native review pending |
| `uk`   | Ukrainian  | Machine-assisted translation, native review pending |
| `de`   | German     | Machine-assisted translation, native review pending |
| `be`   | Belarusian | Machine-assisted translation, native review pending |
| `kk`   | Kazakh     | Machine-assisted translation, native review pending |

Every non-English file starts with `# Machine-assisted translation - native review pending`.
After a native speaker has reviewed a locale, update its row here. Remove the header only
once every file in that locale has been reviewed.

## Files

Each locale has the same six files. Message ids carry the file name as a prefix
(`web-login-title` lives in `web.ftl`) because all six files share one Fluent bundle:

- `common.ftl`: shared labels (buttons, states, counts)
- `web.ftl`: Web UI navigation, sign-in and page chrome
- `cli.ftl`: command-line output
- `domains.ftl`: router domains (system, interfaces, Wi-Fi, clients, routing, VPN)
- `migrate.ftl`: configuration migration
- `errors.ftl`: errors shown to users

## Plurals

Plural variants follow the CLDR cardinal rules: `ru`, `uk` and `be` use
`one`/`few`/`many`/`other`; `en`, `de` and `kk` use `one`/`other`. Fluent selects the
category from a numeric `$count`. `crates/kcc-i18n/tests/fixtures/plurals.txt` pins the
output for 1, 2, 5 and 21 in every locale.

## Locale negotiation

`Locale::negotiate` picks, in order: the signed-in user's preference, the `kcc_lang`
cookie, the best supported entry of `Accept-Language` (highest `q`, ties keep header
order), the configured default, and finally `en`. Only the language subtag matters, so
`kk-KZ` selects `kk` and `be-BY` selects `be`.

## Workflow

1. Add or change the message in `locales/en/<file>.ftl`.
2. Run `cargo xtask i18n-gen` to regenerate `src/keys.rs`. The output is deterministic,
   and `i18n-check` fails if the file is stale.
3. Add the message to the same file in every other locale, keeping the same variables.
4. Run `cargo xtask i18n-check`. It requires the same files and message ids in every
   locale, the same variables in each message, no empty values, valid Fluent syntax and
   the review header on non-English files. Use `--locales-dir <dir>` to check a copy.

`kcc_i18n::bundle::tr(locale, key, args)` formats a message. A message missing from
`locale` falls back to `en`, and debug builds log a warning. Bundles disable Unicode
isolation marks, so the output can go straight into HTML.
